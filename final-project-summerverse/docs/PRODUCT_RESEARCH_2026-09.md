# SummerVerse 产品研究与落地选择

检索日期：2026-09-12。范围：12 个国内外代表产品的官方产品页、帮助文档、公司公告，以及现有小程序代码。它是有边界的公开资料研究，不代表穷尽全市场，也不代表逐一实测了付费产品。第三方仿冒官网、转载榜单和厂商自报性能排名未作为选型证据。

本文中【已核实】指本次读取到的文档或代码事实；【判断】指针对本项目的设计选择；【待实现】指方案，不代表上线。发布状态始终以 [ACCEPTANCE_STATUS.md](ACCEPTANCE_STATUS.md) 为准。

## 产品定位

【判断，按用户2026-09-12纠正更新】更有辨识度的定位是：**手机收集，电脑接着做，结果回到手机。** 使用场景从暑假记录扩展到课程作业、团队讨论、项目推进和求职准备；小岛与记忆保留为个人成长的表达层。

老师发布作业链接和补充通知 → 手机选资料并提出任务 → 自己电脑上的 AI 助手领取 → 结合本地项目处理 → 回传结果与出处 → 手机核对。这条流程连接了手机的资料入口和电脑的实际工作环境。差异在产品组合与工程实现，不宣称基础模型创新或行业首创。

【转述】用户明确指出“答辩练习网页端AI也可以做”，要求优先完善已有本地AI/MCP连接。因此下方研究中的学习机制只作可选补充，原本将答辩预演列为P0的建议已被替代。

## 与当前代码的关系

【已核实】调研开始时 `miniprogram/app.json` 注册14个页面；本轮加入专注和电脑接力后为16个。`docs/MATERIALS.md` 和 `cloudfunctions/deepseekProxy/material-ai.js` 已有提取要求、对比变更、问资料、检查清单、讨论纪要；`material-policy.js` 校验引用是否存在于材料片段，任务由用户接受后保存。已有的底座是资料来源、版本冲突处理和人工确认。

【已核实】当前来源包括文字、图片识字、PDF 文字层、DOCX/PPTX 文字和公开网页。文件选择器不提供整段聊天记录。当前工作台上限是 6 份来源、4 万字、120 个片段、40 项任务。网页提取不等于浏览器渲染，也没有网站登录态。引用匹配只能证明引文存在，不能证明模型解释正确。

【判断】优先复用这些数据契约和出处校验，让新功能直接消费同一份资料。增加模式不应另建多份记忆、复制工作台或切换账号，也不能把新模式当作另一套权限。

## 本轮的落地选择

以下标明本地实现与后续候选；云端和实际客户端验收仍需在验收记录中分别登记。

### P0：手机与电脑 AI 的任务接力

【已核实，本地代码】首页和资料工作台可选定资料、指定授权连接并发起任务；服务器从用户自有工作台冻结所选来源和版本。电脑端增加 `summerverse_jobs`、`summerverse_claim_job`、`summerverse_complete_job`，与旧投递草稿工具共6项。结果回到手机单独核对，不直接改记忆或目标。

【判断】优先演示“手机收到课程补充要求，电脑助手结合已有代码检查并补充交付说明”。真正价值来自电脑当前项目和已有工具环境，不依赖复制一个聊天界面。MCP适配器本身不读取本地文件、不执行shell、不自动轮询；这些操作由用户的电脑AI客户端和现有授权决定，小程序不会远程开机或自动启动一个AI任务。

【已核实】使用标准MCP自定义工具与本地stdio传输；不宣称已实现协议中的实验性Tasks能力，也不把HTTP业务网关地址当作远程MCP服务。官方依据：[MCP Tasks状态](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks)、[Claude Code MCP](https://code.claude.com/docs/en/mcp)、[客户端安全边界](https://code.claude.com/docs/en/security)。具体协议、授权与待完成部署见 [ASSISTANT_BRIDGE.md](ASSISTANT_BRIDGE.md)。

### P0：同一软件的三种使用模式

【已核实，本地代码】简洁模式、专注模式、记录模式共享数据；只调整默认入口、首页重点和信息密度。

| 模式 | 首屏重点 | 按需展开 | 验收标准 |
|---|---|---|---|
| 简洁 | 一个明确主操作、最近资料或当前事项 | 其余工具与设置 | 首次打开知道下一步点哪里；切换后不丢草稿和资料；长标题不挤压操作 |
| 专注 | 已确认任务与按需开启的专注计时 | 记忆地图、装饰性成长内容 | 任务来源可找回；计时结束不会自动完成任务或制造学习时长 |
| 记录 | 小岛、生活记忆、成长与回顾 | 资料分析与工作工具 | 旧入口可达；真实记录、AI 推演仍明确区分 |

【判断】同一套留白、字体层级、按钮体系和颜色令模式保持统一。保留小岛的温度，但让工作场景少一点大图和重复说明。没有必要增加多套网页框架、动画引擎或按模式复制页面。

### P0：资料直接生成行动草稿

【已核实，本地代码】新增“行动拆解”：从用户资料中生成少量任务、核对事项和需要问老师的问题。用户接受后写入已有任务区。资料未写截止时间时保持未知，不替老师编工期、优先级或责任人。

输入示例：“周五交 PDF”+“补交通知要求附代码链接”。输出：准备 PDF、核对代码链接是否已附、若存在两种截止日期则列为待确认；每项带片段出处。只生成清单不能声称完成了实际交付检查。

验收：重复点击不重复加任务；网络失败保留当前内容；旧工作台能够恢复；无出处的事实性行动拒绝接收；用户可以不接受建议。

### 可选：有出处的汇报练习（已移出主线）

【已核实，本地代码】资料工作台“更多场景”保留练习入口。上传自己的项目说明、课程要求或简历素材，生成少量练习问题。先看到问题，自己组织回答，再展开参考要点和出处。界面不默认展示参考答案，不显示“通过面试率”“老师预计给分”或无依据的能力评分。该入口不是首页主操作，也不作为求职作品的主要创新叙事。

例如：“这个项目解决了什么问题？”“你为什么选择云函数？”“哪些能力还没验证？”参考要点必须来自实际导入材料；材料缺少部署证据时，提示补充而不是替用户写“已上线”。

验收：每个练习条目有可校验的引用；问题与参考答案成对恢复；无来源材料不得产生看似专业的答辩题；用户回答不被自动记作事实或发送给额外服务。

### P1：提交前的缺口与变更核对

【待实现】在已有“检查清单”和“对比变更”上，突出“原要求—现有证据—待确认”。它不是通用评分器，而是帮用户发现未提供的材料或互相冲突的通知。

例如：要求有演示视频，但用户没有上传视频或相关说明，就显示“本次资料中未找到演示视频证据”；不能直接断言用户没有录制。新通知日期较晚不代表它一定更权威。它和行动拆解共同构成一个可解释的决策过程。

### P1：可展示的项目复盘卡

【待实现】用户从已确认任务和真实记录中选择内容，整理“问题—我的决策—完成的工作—证据—还需改进”，形成自己的项目复盘。导出前预览、主动选择分享对象，标注 AI 辅助整理。

【判断】它有求职价值，因为让开发者讲清自己的取舍和证据；不自动编造使用人数、节约时间、性能倍数、获奖情况或团队贡献。第一版可以是简洁文字卡，漂亮动画不是必要前提。

## 为什么现在不堆上全部前沿能力

| 想法 | 【判断】现在不优先的原因 | 可落地的替代 |
|---|---|---|
| 自动读取微信群全部聊天、语音和成员 | 当前微信公开选择接口没有这些权限；群内他人的信息也需要处理依据 | 用户主动复制、选文件、选截图；显示读取范围 |
| 自动打开任意链接、登录教务或绕过验证码 | 会引入凭据管理、站点授权和网页攻击面 | 已有公开网页提取；登录内容由用户选择正文导入 |
| 无限深度研究 / 多模型集群投票 | 显著增加延迟与费用，多个模型也可能共同出错 | 一次分析调用，结构化结果校验，出处与用户确认 |
| 整库向量搜索、跨用户共享知识广场 | 当前每工作台数据有限；跨用户索引会增加权限与检索泄漏风险 | 先做好有限资料内的可追溯分析；未来有真实容量需求再评估 |
| 自动发群消息、交作业、替用户预约或支付 | 外部服务许可、不可逆提交和金额确认不同于生成文本 | 草稿预览+用户主动复制或分享 |
| AI 心理诊断、医疗/投资/法律结论 | 高风险专业服务不是本项目的能力与资质范围 | 保持学习、工作材料处理和普通生活记录 |
| 语音克隆、实时视频伙伴、无限生成小岛 | 增加模型成本、敏感信息与标识复杂度，降低首屏速度 | 阶段插画、可关闭轻动效、清晰的真实成长记录 |
| 完全自动永久记忆 | 过度收集、误记事实与难以纠正会伤害体验 | 明确保存范围、查看/修正/删除；AI 草稿不直接入事实记忆 |

【判断】设置页要分清：聊天 App 的会员、编程套餐和开放平台 API 是不同权益；不能让用户以为有聊天会员就必然有 API 额度。免费模型也受其平台限流和策略约束；自己的 API Key 不代表流量无限或数据绝不离开设备。引用海外产品只用于研究设计，默认服务商继续用上述国内平台。

## 体验与鲁棒性的落地标准

【判断】“高级”应表现为可预测：点一下有反馈、失败能恢复、资料不会悄悄丢、AI 不装懂。无法保证所有未知边界永远无问题，应建立可重复检查的范围与可定位的失败信息。

| 重点 | 具体工程策略 | 证据要求 |
|---|---|---|
| 快速首屏 | 先显示本地已确认内容；按页/组件加载；避免首屏同时请求所有功能；大图按显示尺寸准备 | 同一设备记录首屏可操作时间与包体，不用主观“秒开” |
| 点击与切换 | 防重复提交、异步请求归属校验、离页不再写旧页面；模式切换保存偏好 | 连点、返回、切模式、请求晚到的回归场景 |
| 网络失败 | 展示明确阶段与重试入口；草稿保留；不对可能计费或重复写入操作盲目自动重试 | 断网、超时、429、服务端失败后能继续操作 |
| 长资料 | 在容量边界明确拒绝或请求拆分，不悄悄截断；渲染摘要，正文按需展开 | 超上限、空文件、长标题、异常格式的实际测试 |
| 可信输出 | 严格结构校验、引文匹配、缺证据拒绝；模型结果是待核对草稿 | 伪造出处、错 sourceId、空答案、混合条目类型均有处理 |
| 可访问性 | 字体层级清楚、按钮可点、颜色之外还有状态文字；装饰动画可减少 | 小屏、系统大字、长中文/英文、弹窗与键盘遮挡检查 |
| 数据恢复 | 保存状态可见；云端冲突显式报错；模式不创建另一份数据 | 重开工作台、旧版本数据、并发修改验证 |
| 费用可理解 | 不默认多模型竞赛；动作有目的、调用有上限；失败不伪造成功 | 记录请求次数与失败归因，不存原始 Key 和敏感资料日志 |

以上是测试与性能目标，不是本轮已达成的数字承诺。确认真正瓶颈后再优化，避免未经测量把所有页面换成新框架。

## 国内上线与隐私边界

【已核实】《个人信息保护法》要求目的明确、范围最小，并向用户说明处理方式；依据是[网信办刊载法律正文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。据此，本项目应保留明确的资料导入、云保存及发送模型服务商的告知，不自动抓取剪贴板或背景聊天。

【已核实】[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)规定了适用服务的显式、隐式标识与下载、复制、导出场景要求，并自 2025-09-01 起施行。具体适用义务应按实际服务和平台要求核对；不能把“采用国内模型”或“用户自己填 Key”作为产品已全部合规的证明。

【判断】本轮保持 AI 草稿和出处标识；导出不能去掉 AI 辅助说明。正式发布前仍需核对微信隐私指引、类目及实际 AI 功能申报，材料类型、模型接收方变化也要同步说明。产品研究不是法律合规审定。
