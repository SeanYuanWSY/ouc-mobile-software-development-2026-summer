# 实验四：推箱子游戏

一个使用微信小程序 Canvas 和绘图 API 完成的推箱子小游戏，包含 4 个课程关卡和 4 个原创扩展关，地图均为 8×8。

## 功能

- 首页展示 8 个关卡，清晰区分课程关卡与扩展关卡
- 关卡按最短通关步数递增排列，原有成绩仍与对应地图绑定
- Canvas 绘制墙面、冰面、目标、箱子和角色
- 方向按钮与棋盘滑动两种操作方式
- 完整的碰撞、推箱和通关判断
- 重新开始、撤销一步、步数和推动次数统计
- 一步提示、两步提示和一句话思路提示
- 从当前局面计算最短路径，并自动演示小鸟通关过程
- 自动通关收在“实在卡住了？”二级入口中：首次挑战锁定，第二次挑战或已通关后解锁
- 首次挑战也可以在二级入口中点击“直接解锁自动通关”
- 通关后显示独立成绩页，根据路线效率和辅助情况给出 S/A/B/C 等级与分数
- 使用提示或自动演示的对局不写入个人最佳纪录
- 本地保存每一关的最佳步数与用时

## 运行

在微信开发者工具中导入当前目录，编译后从首页选择关卡即可开始。项目素材来自课程提供的 `boxgame_images.zip`。

## 自动通关算法

自动通关使用广度优先搜索（BFS）。程序把“小鸟位置 + 所有箱子位置”作为一个局面，从当前局面开始逐层尝试上、下、左、右四种移动，并跳过重复局面和箱子卡在非目标墙角的死局。因为 BFS 按移动步数逐层搜索，所以第一次找到的通关路线就是移动步数最少的路线。一步提示、两步提示和自动演示都使用同一条实时计算出的路线，不是预先写死的操作序列。

## 评分与解锁

评分以 BFS 算出的最短移动步数为基准。最优路线为 100 分，多走的步数越多，路线效率分越低；使用提示时最高 80 分。自动演示只显示最优路线和“演示完成”，不计算等级与个人分数。推动次数和用时会展示在成绩页中，但不会影响分数，避免不同地图的箱子数量和暂停操作影响公平性。

## 目录

```text
├── images/          # 关卡预览图与游戏图标
├── pages/index/     # 关卡选择页
├── pages/game/      # Canvas 游戏页
├── utils/levels.js  # 八关地图数据与难度顺序
├── utils/scoring.js # 通关评分与等级规则
└── utils/sokoban.js # 移动、推箱、胜利判断与 BFS 求解
```
